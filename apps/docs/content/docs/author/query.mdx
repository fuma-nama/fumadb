## Basic Usage

To interact with the ORM:

1. Get the active schema version.
2. Get the ORM instance for the given version.

```ts
const version = await client.version();

const orm = client.orm(version);
```

It's useful when you have multiple versions and want to ensure backward compatibility.

```ts
const version = await client.version();

if (version === "1.0.0") {
  const orm = client.orm(version);
  // ...
} else if (version === "1.1.0") {
  const orm = client.orm(version);
  // ...
}
```

### Create

```ts
const createdUser = await orm.create("users", {
  name: "fuma",
});
```

### Create Many

```ts
await orm.createMany("users", [
  { id: "alfon", name: "alfon" },
  { id: "bob", name: "bob" },
]);
```

### Find Many

```ts
const allUsers = await orm.findMany("users", {
  select: true, // or ["id", "name"]
  orderBy: [users.name, "asc"],
});
```

- `select`: true, or array of column names
- `where`: (builder) => condition
- `orderBy`: [[column, "asc" | "desc"]]
- `limit`, `offset`
- `join`: (builder) => builder.relation(...)

### Find First

Same as `findMany` but only return the first result in the query.

```ts
const user = await orm.findFirst("users", {
  where: (b) => b("id", "=", "alfon"),
});
```

### Update Many

```ts
const { count } = await orm.updateMany("users", {
  set: { name: "Bob" },
  where: (b) => b("id", "=", "alfon"),
});
```

`count` is the number of rows matched by `where`, also when the new values equal the current ones. Use it to tell whether a conditional write landed:

```ts
const { count } = await orm.updateMany("links", {
  set: { revokedAt: new Date() },
  where: (b) => b.and(b("id", "=", id), b.isNull("revokedAt")),
});

if (count === 0) {
  // already revoked, or no such link
}
```

On MySQL, this relies on the `CLIENT_FOUND_ROWS` flag, which `mysql2` and `mariadb` enable by default. If your client disables it, MySQL counts only the rows whose values changed.

To update a number relative to its current value, use `increment()`. It runs in the same statement, so concurrent updates are never lost:

```ts
import { increment } from "fumadb/query";

await orm.updateMany("links", {
  set: { viewCount: increment(1), credits: increment(-5) },
  where: (b) => b("id", "=", id),
});
```

It works on `integer`, `bigint` and `decimal` columns, in `updateMany` and in the `update` of `upsert`. A negative step decrements, and a null stays null. Use a `bigint` step for `bigint` columns, e.g. `increment(1n)`.

### Upsert

```ts
await orm.upsert("users", {
  where: (b) => b("id", "=", "bob"),
  create: { id: "bob", name: "Bob is sad" },
  update: { name: "Bob is happy" },
});
```

The query is executed when awaited. To receive the created/updated row, call `forceReturning()` instead:

```ts
const user = await orm
  .upsert("users", {
    where: (b) => b("id", "=", "bob"),
    create: { id: "bob", name: "Bob is sad" },
    update: { name: "Bob is happy" },
  })
  .forceReturning();
```

Databases that can return the affected row (such as PostgreSQL, SQLite and MS SQL Server) obtain it from the write itself, the others run one extra query for it.

### Count

```ts
const count = await orm.count("users", {
  where: (b) => b.isNotNull("name"),
});
```

### Delete Many

```ts
const { count } = await orm.deleteMany("users", {
  where: (b) => b("id", "=", "bob"),
});
```

`count` is the number of deleted rows. Rows removed by cascading foreign keys are not included.

## Filtering & Conditions

The query builder (`b`) supports logical operators and comparisons:

```ts
const filtered = await orm.findMany("users", {
  where: (b) => b.and(b("name", "contains", "al"), b.or(b("age", ">", 100), b.isNull("email"))),
});
```

Supported operators include:

- `=`
- `!=`
- `>`
- `>=`
- `<`
- `<=`
- `in`
- `not in`
- `contains`
- `starts with`
- `ends with`
- `not contains`
- `not starts with`
- `not ends with`

String operators like `contains` match the value literally, so `%` and `_` are not wildcards. The Prisma adapter is the exception: on SQL databases, Prisma treats `%` and `_` as wildcards.

### Comparing Columns

To compare a column against another column of the same table, pass `b.ref()` as the right-hand side of `=`, `!=`, `>`, `>=`, `<` or `<=`:

```ts
const openLinks = await orm.findMany("links", {
  where: (b) => b.or(b.isNull("maxDownloads"), b("downloadCount", "<", b.ref("maxDownloads"))),
});
```

Both columns must have the same value type. Like SQL, a null on either side never matches, on every adapter.

## Joins (Relations)

For relations, make sure to [declare relations](/docs/author/schema#relations) in your schema first.

```ts
// Get users with their messages
const result = await orm.findMany("users", {
  join: (b) => b.messages(),
});

// Nested join with select and where
const result = await orm.findMany("users", {
  join: (b) =>
    b.messages({
      select: ["content"],
      limit: 1,
      where: (b) => b("content", "contains", "alfon"),
      join: (b) => b.author(),
    }),
});
```

## Unique Constraint Errors

When a write violates a unique constraint or the primary key, `create`, `createMany`, `updateMany` and `upsert` throw a `UniqueConstraintError` on every adapter:

```ts
import { UniqueConstraintError } from "fumadb";

try {
  await orm.create("folders", { parentId, name });
} catch (e) {
  if (e instanceof UniqueConstraintError && e.constraint === "folders_parent_name_uk") {
    throw new Error("FOLDER_EXISTS");
  }

  throw e;
}
```

`constraint` is the name of the unique constraint in your schema. It is `undefined` for the primary key, or when FumaDB can't tell which constraint failed. The error from the database driver is available as `cause`.
