---
title: Overriding Names
description: Override table/column names to avoid conflicts with your database.
---

## Overview

To override names in FumaDB, you can use the Name Variants API.

For example, if the schema has a `messages` table which conflicts with yours, you can override it:

```ts
import { fumadb } from "fumadb";

// assuming the library exported
const ChatDB = fumadb();

const client = ChatDB.names({
  messages: {
    sql: "chat_user",
    prisma: "ChatUser",
    drizzle: "chatUser",
  },
  // or to rename columns
  "messages.id": {
    sql: "message_id",
  },
}).client();

// for specific versions
const client = ChatDB.names(["1.0.0"], {
  messages: {
    prisma: "ChatUser",
  },
}).client();
```

You can also apply a prefix to all tables:

```ts
const client = ChatDB.names.prefix("chat_").client();
```

## Database Schema

To place tables in a PostgreSQL schema, add the schema to their SQL name:

```ts
const client = ChatDB.names({
  messages: { sql: "chat.messages" },
}).client();

// or for all tables
const client = ChatDB.names.schema("chat").client();
```

The migrator creates the schema, and moves existing tables into it. The internal settings table of FumaDB stays in the search path.

For Prisma, list the schemas in your datasource:

```prisma
datasource db {
  provider = "postgresql"
  schemas  = ["public", "chat"]
}
```

<Callout type="warning" title="Be Careful">

Make sure to migrate your database if you've updated the name variants.

</Callout>
